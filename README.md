# BalloonTranslator

**一款面向 Windows 的漫画翻译工具，致力于让日文漫画翻译更加方便、清晰、自然。**

- 仓库地址：[shuxuanliang95-create/BalloonTranslator](https://github.com/shuxuanliang95-create/BalloonTranslator)
- 当前重点：改善 v12.6 翻译文字的大小、清晰度和醒目程度，同时保持现有功能稳定。

## 快速开始：安装与使用

首次使用前，请按 [INSTALL.md 安装指南](INSTALL.md) 准备 Python 3.11、Python 依赖、Ollama 本地翻译模型，以及 OCR 和 LaMa 图像修复模型。**仅下载仓库代码还不够，模型文件需要按指南单独准备。**

- **安装依赖：** 双击 `install_windows_v12_6.bat`
- **下载 OCR 模型：** 双击 `download_ppocr_manga_models.bat`
- **下载擦字修复模型：** 双击 `download_manga_inpaint_model.bat`
- **启动程序：** 确认 Ollama 中已准备好 `hy-mt2-7b`，然后双击 `start_windows_v12_6.bat`
- **打开界面：** 在本机浏览器访问 http://127.0.0.1:7860

注意：当前安装脚本没有显式安装 PyTorch，而 LaMa 擦字修复功能需要 PyTorch；具体安装方式请参照 [INSTALL.md](INSTALL.md) 中的说明。上述步骤尚需在目标电脑上实际验证，遇到问题请提交日志和环境信息。

**需要帮助？** [查看安装指南](INSTALL.md) · [提交 Bug 报告](.github/ISSUE_TEMPLATE/bug_report.md) · [贡献指南](CONTRIBUTING.md)

## 1. 项目介绍

BalloonTranslator 是一个面向日文漫画翻译场景的 Windows 工具，目标是帮助用户处理漫画图片中的日文文字，并将翻译结果显示在漫画画面中。

项目涉及文字识别、文本翻译、图像处理、文字绘制及运行环境配置等环节。欢迎 Python、OCR、图像处理、日语翻译及 Windows 打包相关开发者参与测试、排查问题和提出改进建议。

> 本文中的问题清单主要来自实际使用反馈；除非明确标注为已验证，否则仍需在可复现的测试环境中确认。

## 2. 当前开发目标

目前最重要的目标是：**在保持现有翻译效果和功能的基础上，提高翻译文字的可读性与整体稳定性。**

重点关注：

- 增大翻译文字，使其在漫画画面中更容易阅读。
- 增强文字的清晰度、对比度和醒目程度。
- 优化文字描边及复杂背景下的可读性。
- 改善竖排文字的排列和显示效果。
- 排查文字显示异常、局部空缺、图像修复痕迹等问题。
- 保持批量处理界面的原有布局与使用方式。
- 改善 Windows 环境下的安装、启动和依赖配置体验。

## 3. 版本反馈与已知问题

### v12.4：重要的视觉对比基准

此前使用反馈认为，v12.4 的部分文字显示效果优于后续尝试版本。后续改进应将 v12.4 作为重要的视觉对比基准，重点观察文字位置、排列、背景融合、异常空缺、竖排倾斜及批量处理界面。

### v12.5 及后续尝试：需要对比验证

此前反馈提到过文字显示不够理想、局部出现异常空缺，以及部分文字排列不自然等现象。需要使用相同输入图片、相同配置和相同处理流程进行对比，以确定问题来自哪个环节。

### v12.6：当前重点改进版本

使用者反馈 v12.6 的整体效果不错，但翻译文字仍然偏小、不够醒目。当前优先方向：

1. 在不破坏现有翻译效果的前提下，适当增大文字。
2. 改善描边、对比度及复杂背景下的可读性。
3. 检查横排与竖排文字的显示一致性。
4. 避免调整文字大小时引入新的空缺、错位或图像伪影。
5. 不随意改变批量处理界面及既有使用流程。

建议优先采用小范围、可验证、方便回退的修改方案，而不是直接重写整套翻译流程。

## 4. 欢迎协助排查的问题

### A. 翻译文字太小、不够醒目

希望研究如何合理调整字体大小、描边宽度、文字颜色和对比度。

**期望结果：**
- 文字更容易阅读，轮廓清晰。
- 不会因字体变大而明显超出原有文字区域。
- 横排、竖排文字都能正常显示。
- 不明显增加文字重叠或遮挡。

### B. 局部文字显示异常或出现空缺

此前测试图片曾出现类似异常，具体成因尚未确认。建议检查文字区域检测和裁切、图像修复或背景填充、文本遮罩与绘制边界，以及字体描边和抗锯齿。

请先通过对比输出图片和中间处理结果定位问题，不要在原因不明时大范围修改代码。

### C. 竖排文字排列不自然

希望检查竖排文字的绘制方式、字符间距、行距、文字方向和边界计算。

**期望结果：**
- 字符排列自然、方向正确。
- 不出现明显倾斜、错位或裁切。
- 描边效果与横排文字保持一致。
- 多行或较长文字不会明显溢出。

### D. Windows 安装或启动失败

曾遇到 Python 依赖安装失败，报错涉及 `torch` 和 `torchvision`，安装命令使用了指定版本的依赖及项目运行环境中的 Python 解释器。

希望协助确认：
- Python 版本与依赖版本是否匹配。
- PyTorch 与 Torchvision 的版本组合是否兼容。
- 是否存在网络下载、安装源或平台兼容性问题。
- 安装脚本能否清楚提示失败原因，并允许安全重试。

目前根因尚未确认，不应在没有完整日志的情况下直接认定为某个依赖版本的问题。报告问题时请附完整报错、Python 版本、Windows 版本和执行的命令；上传前请移除令牌、密钥和个人路径等敏感信息。

### E. 字体来源与许可证

项目包含 `NotoSansSC.ttf` 字体文件，但该文件的确切来源和版本尚未核实。希望协助核对字体元数据、原始来源及对应许可证，并在确认后补充正确的版权声明和许可证文本。

在确认之前，不应随意替换字体文件，也不应添加未经核实的版权信息。

### F. 项目结构与自动化测试

欢迎检查依赖清单是否完整、Windows 启动脚本是否与实际 Python 环境一致、自动化测试配置是否引用了缺失的文件或环境配置，以及是否可以为文字布局、字体绘制和基本启动流程增加测试。

请先说明发现的问题和建议方案，不要删除尚未确认用途的文件。

## 5. 修改原则

1. 修改前先阅读相关代码并尽可能复现问题。
2. 优先采用范围明确的小改动，并说明每项修改的目的。
3. 不要随意重写 OCR、翻译、图像修复或字体绘制流程。
4. 不要随意改变批量处理界面的既有布局和使用方式。
5. 修改前后尽量使用相同测试图片进行对比。
6. 视觉改动尽量提供修改前后的图片。
7. 提交时说明修改文件、测试方法、测试结果和已知限制。
8. 没有实际运行验证的功能应明确标注，不能声称测试通过。

## 6. 如何报告问题

提交问题时，尽可能提供：

- 使用版本，例如 v12.4 或 v12.6。
- Windows 版本和 Python 版本。
- 发生问题时执行的操作。
- 预期结果与实际结果。
- 可复现的输入图片或已脱敏的示例。
- 完整报错信息或终端日志。
- 若是显示问题，请提供原图和处理后的图片。
- 如果问题只在某些图片出现，请说明共同特点。

请勿上传 API 密钥、密码、私人漫画文件或其他未经授权公开的内容。提交前请检查日志中是否包含令牌、用户名、个人目录或其他隐私信息。
